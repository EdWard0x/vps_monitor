把下面代码块中的内容复制到能够访问本仓库的模型任务中。若模型无法访问仓库，需要同时提供交接文档和相关前端源码，仅提供提示词不足以完成实现。

```text
请在当前 VPS Monitor 仓库中直接实现用户 VPS 收藏的前端功能，不只给出方案。

先阅读 docs/frontend-favorites-sync.md，然后核对当前后端 backend/router/user.go、backend/api/favor.go、backend/service/favor.go 与现有前端结构。如果工作区实现较文档有变化，先核实差异，不凭旧接口假设继续。

已有后端接口，均要求登录：
- POST /api/v1/me/addFavor?vpsId=<字符串ID>
- DELETE /api/v1/me/delFavor?vpsId=<字符串ID>
- GET /api/v1/me/listFavors，支持现有 VPSQuery 筛选、排序和分页。
写接口返回 Envelope<string>，data 为 "success"。列表返回 Envelope<PageData<VPS>>，产品 ID 为 item.id。写参数必须在 URL query 中，名称是 vpsId，不是 JSON body 中的 vps_id。

需要实现：
1. 登录用户在公开 VPS 卡片右上角使用空心/实心星星收藏或取消，未登录隐藏星星且不请求收藏数据。覆盖首页、商家详情页，并在 VPS 详情页提供相同操作。
2. 个人中心增加“我的收藏”入口。建议新增受 AuthGuard 保护的 /account/favorites 页面，复用 VpsFilter、VpsCard 和分页组件，实现服务端商家筛选、价格升降序、币种/周期/库存/关键词筛选、分页和取消收藏。
3. 复用现有 apiClient、useAuth、类型、样式和 Toast/ErrorState；使用 Context/hooks 管理按用户隔离的收藏状态，避免为了此功能引入新的全局框架。
4. 同一 VPS 在途请求共享防重入，快速连点不能并发发出相反操作；成功才确认新状态，失败可恢复和重试。不同入口的状态保持一致；账号切换、旧读取响应和旧写入响应不能污染当前状态。

特别注意：当前没有收藏状态接口，公开 VPS 接口也没有 is_favorited。使用现有 listFavors 分页获取全部可见收藏（每页最多 100），建立共享 ID Set。不能只取第一页，不能把个人收藏页面的筛选结果当成全局收藏集合，不能每个卡片独立拉全量。初次加载未完成或部分请求失败时，不把未知状态假装成未收藏。不要编造 /favorites/status 等接口。遵守文档中的用户隔离、请求代次、变更后同步及分页一致性限制。

保持原有产品详情库存轮询、购买链接和其他账号功能。星星按钮应有键盘和屏幕阅读器支持，移动端无布局重叠。收藏页面取消后处理总数和最后一页回退，查询失败与空结果分开显示。

维护者暂不要求同步前端错误码全集。后端数据库错误当前为 500001，而前端旧常量仍是 400001。不要依赖旧常量判断收藏操作成功；沿用 HTTP 层对错误的处理和服务端 message。不要为此擅自修改后端。文档已经记录后端全量测试编译的已知问题，不要把它们归因于本次前端改动，也不要声称已通过全量后端测试。

补充 MSW mock 和有意义的测试，覆盖：未登录、首次状态加载、超过 100 条收藏、添加/取消、重复操作、快速连点、请求失败、跨账号隔离、迟到响应、筛选分页及取消最后一项。不要仅用本地状态做演示，真实模式必须调用真实接口。

在 frontend 运行 npm run typecheck、npm test、npm run build，并实际检查页面交互。若因环境限制不能运行某项，明确说明，不伪称通过。不要覆盖工作区已有后端改动，不创建提交或部署，除非我另行要求。

完成后简要汇报：修改文件、实现效果、验证结果、仍有的限制。请直接推进实现，不停留在计划阶段。
```
